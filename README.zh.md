# dsh-qq-chat

[English](README.md) | 中文

## 概要

让消息对话在 DSH 重启后延续、让不同会话并行处理，并在连接消息通道前于本地检查回复。这个可独立安装的 bundle 提供原生设置页和文字试用，保留已接纳的原始消息，在发送前保存发送意图，发送结果未知时不会自动重试。安装后默认关闭自动聊天。本候选包覆盖文字调度；媒体感知、复杂接话和完整离线实验室属于独立能力。

<a id="use-this-package"></a>
## 使用本包

### 安装与配置

使用 DSH **0.2.2-rc.1**、Cordis 4.1、Node **^22.19 或 >=24**，以及独立共用库 **dsh-im-kit 0.2.0**。已验证的宿主与 profile 依赖来自同一份 DSH 安装。本候选包不支持混合不同物理安装：该 DSH 预发布版本的预设作用域使用包内运行时标识。模型凭据、预设、agent 和会话持久化均由 DSH 管理，本包不复制它们。

本包是本地候选包，尚未发布到注册表。已有安装好上述依赖的 profile 与本包压缩包时，已验证的 bundle 操作为：

```text
dsh plugin --profile <profile> add <path-to-dsh-qq-chat-0.1.0.tgz>
```

通过 `dsh` 启动该 profile。在原生插件页打开本 bundle 的配置页，选择预设与模型或沿用宿主选择，再启用聊天并保存。页面分别显示已保存版本与实际运行版本。无效编辑保留草稿；重启保留消息收据和会话映射；关闭自动聊天后控制页仍然可用。本包不提供独立应用程序入口或额外设置服务。

### 不连接 QQ 试用

在同一页使用**本地文字试用**。它采用已保存配置、DSH 原生 agent 和正式的收据、排队、输出流程，在本地捕获公开出站文字，不会经消息通道发送。试用始终禁用工具，使用独立持久会话支持连续追问；取消某一次试用不会取消正常会话。这是文字检查，不是媒体与工具的全链路实验室。

实时消息可选地消费独立消息插件提供的 `ctx.im`，例如 `dsh-qq-onebot`。群聊基础触发按配置接受通道确认的明确寻址或同一发件人的近期追问。可选的 `qqTurnPolicy` 提供方可对其他未明确寻址的群消息选择回复或忽略；明确寻址和私聊仍会受理。原始来源不变，提供方报错会先发出诊断，再回退到基础策略。私聊与群聊、不同账号、不同预设，以及试用和真实消息分别映射。多人话题归属和机器人循环控制仍未完成。

群聊默认共享模型会话。开启 `isolateGroupSenders` 后，每个群、预设、账号中的各成员使用独立会话；私聊不变。开启时从独立历史开始，原有共享会话保留；关闭后恢复使用共享会话。此选项只隔离模型会话日志，不控制群内公开回复、工具权限、其他插件或发件人身份认证；目前也不会接入历史搜索或向各独立会话注入群共享上下文。

安装接话策略时，所有群消息先进入本地收据库，再由策略判断，包括之后被忽略的消息。重复或过期消息不会调用策略；通道不可用或被禁言时不会调用策略的决策方法。策略判断使用配置的排队等待上限，超时后回退基础触发；提供方须在收到中止信号后停止自己的工作。策略可以观察新群消息而不执行决策，因此实现必须限制保留的上下文。本收据库不能替代群聊归档和长期记忆。

### 工具与限制

可执行工具允许名单默认为空。适配器隐藏未列入名单的全局工具定义，并校验每次执行的工具名，包括预设作用域内的工具。DSH 0.2.2-rc.1 仍可能在执行前展示这些作用域工具定义，实际执行会被检查拒绝。允许某工具不等于将已安装宿主代码或其内部副作用置于沙箱中；只应启用可信预设和插件。

原生页面展示所有运行配置项，包括队列与并发、输入输出大小、模型/发送/存储等待上限、存储路径与会话缓存限制。提供方与模型必须一起填写。模型、预设、思考强度留空时沿用宿主选择；输出 Token 上限 `0` 表示沿用宿主限制；存储路径留空则解析到当前 profile。重复来源不会再次调用模型或发送；同一来源 ID 对应不同正文时视为冲突。

<a id="persistence"></a>
## 持久化

默认收据库位于当前 profile 的 `data/qq-chat/state.sqlite3`。SQLite 在专属 worker 中运行，等待数据库锁不会阻塞宿主事件循环。一个活跃进程独占数据库；应用标识与单调递增的格式版本拒绝外来或未来数据库。格式 1 在事务中迁移至格式 2，保留原始来源字节，将以前未记录的模型结果标为未知；见[迁移指南](docs/upgrade-guide/v0.1.0/journal-v2/guide.zh.md)。

收据库保留已接纳的原始消息、请求结果、映射元数据与发送意图。重启将待处理任务标为中断，不会自动重放旧回复。模型结果与发送结果分别记录：错误提示发送成功不代表模型成功。发送结果未知不会重试。会话日志仍由 DSH 原生持久化管理，本 bundle 不重写它们。

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>实现细节——点击展开</summary>

[Bundle 补丁](cordis.patch.yml) 添加常驻的所有者控制器和默认关闭的聊天运行时。运行时持久接纳每个来源，公平调度各会话的先进先出队列，复用有上限的原生会话句柄，刷写日志输入与输出，再在单次发送前保存意图。关闭时取消活跃计算并等待 agent、收据操作和 worker 完成。原生页面采用宿主 Remote/config-editor 服务及配置版本检查；状态查询不读取预设正文或已存消息正文。

</details>

<a id="model-experience"></a>
## 模型体验

选定预设经原生预设注册表加载。已记录的用户消息携带经过通道确认的发件人与会话元数据、被引用的成员载荷，以及上次回答的发送状态，独立于预设。附件引用本身不提供视觉或音频证据。适配器只观察由自己拥有的完整 agent 处理区间，并仅转发最后一条完整公开文字，排除思考、工具调用块与中断输出。额外进入收件箱的输入使转发失效；普通追问保留原生会话历史。

## 已知限制与待完成工作

<a id="known-limitations-and-deferred-work"></a>

- 受控原生适配器测试及原生 Web 测试覆盖安装、取消、作用域工具执行、重载与持久化；真实 DeepSeek API 冒烟只覆盖文字、记忆口令与算术。这些不等于模型能力对比或真实 QQ 客户端验收。
- 本地验证平台为 Windows。Linux CI、真实 QQ 投送、媒体适配、复杂接话与完整离线实验室不在本候选包的已验证范围内。
- DSH 0.2.2-rc.1 热替换核心会话 UI 模块时可能出现 Web 白屏。另一个 pnpm 安装操作即使只改变共享硬链接的文件状态时间，也可能触发替换。隔离测试使用独立文件副本。并发修改共享核心文件仍属于宿主限制，本 bundle 不修改宿主。
- 常见本机路径、私有端点和密钥格式检测属于有限输出检查，不能证明阻止所有泄露方式。状态页不展示聊天或预设正文。
- 测试 Node 版本中的 SQLite 仍是实验模块。活跃数据库所有者不会被强行取代；worker 非正常失败后可能需要重启宿主。来源数据留在本地，本包不加密它们，应保护 profile 目录。
