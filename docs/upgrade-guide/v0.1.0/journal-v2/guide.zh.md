# 聊天收据格式 2

## 变更

使用格式 1 的早期开发收据库没有记录模型结果及上次回答的发送状态。格式 2 增加这些字段，不改动已接纳来源的字节或 DSH 原生会话日志。Worker 在接受新请求前于事务中迁移格式 1。以前未记录的模型结果变为 `unknown`，上次发送状态变为 `null`。格式 1 代码无法读取升级后的数据库；外来数据库和更新格式会被拒绝。

## 迁移

1. 停止拥有数据库的 DSH profile，为收据库及存在的 SQLite WAL/SHM 文件保留一致备份。不要只复制活跃数据库主文件，也不要用两个宿主打开同一个收据库。
2. 保持 `namespace`、`databasePath` 与 `workspacePath` 不变，再使用本候选包启动 profile。Worker 在报告就绪前升级原收据库，不会取代活跃所有者。
3. 检查原生插件状态是否成功启动，以及保留的收据与映射数量。已有待处理任务标为中断，不会重放；新回复分别记录模型与发送结果。
4. 如果启动拒绝数据库，保留原库及备份用于诊断。不要降低 `user_version` 或删除收据库。若需回到旧代码，先停止 profile，再恢复完整的升级前备份；不要覆盖唯一的升级后副本。
